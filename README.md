# 墩迹 TrickTrace

循牌而行，见墩之迹。

浏览器本地图片识牌、桥牌双明手求解与完整最优牌路追踪。

在线测试版：<https://tricktrace.pages.dev/>。源码仓库为私有仓库 `bingingingin/TrickTrace`。

## 使用

顶部明暗开关可切换深色模式，并在刷新后保持选择；首次使用默认浅色模式。深色模式使用白图黑底 Logo。

手动输入时先选方位，再连续点牌；下方 NESW 文本框可以直接编辑，格式为黑桃.红桃.方块.梅花，例如 `AKQ.JT9.432.A765`。`-` 表示缺门，`?` 表示未知手牌。副号自动联动发牌方和局况。截图上传后必须校对，缺牌不会自动补齐。

完整牌局会自动计算定约表。点击表格的至少 7 墩单元格，会设置对应庄家、花色和阶数；点击牌桌上方的定约也能修改。逐张分析中点击手牌出牌，首攻同步显示。自动模式每墩快速出四张，保留四张至少 1 秒后继续；并列最优默认选择最小点数，同点数按黑桃、红桃、方块、梅花排序。

牌桌下方“查看完整最优牌路”展开一条完整 DDS 最优样例。最优不一定唯一；偏离后按新局面重新求解。两家牌分析先在牌桌下方选择首攻（或直接打出首攻牌），随后自动建立临时分析副本，只保留庄家与明手、按约束模拟两家防守牌。原牌例与四家手牌显示保持不变，无需编辑为 `?`；轮到防守方时先打出实际牌，再分析庄家或明手的选择。两家牌模式为采样估计，不代表实际隐藏牌下的必胜策略。

侧边栏的“单明手最佳首攻”为可选功能，默认关闭。模拟默认 1000 次，可选 250、1000、2500、5000 次或自定义 16–5000 次。两家牌与首攻分析共用叫牌和牌型约束：叫牌按官网新睿二盖一（CCBA v2.2，非简易二盖一）自动联动各家点力和花色张数，支持常见开叫、应叫及后续约定；未覆盖进程明确提示。手动修改只覆盖对应字段，改叫牌时保留，可恢复体系推断。点击“开始首攻分析”后，后台 Worker 自动从原始发牌生成临时单明手数据，仅保留首攻方 13 张牌，按约束采样其余三家。无需创建副本，不新增牌例、不改变牌桌或播放进度；关闭后继续原来的基本分析。历史版本已保存的副本仍可手动删除。详细边界见 [首攻约束对照](docs/lead-analysis-comparison.md) 和 [CCBA 规则来源与覆盖](docs/ccba-inference.md)。

首攻默认使用“快速 · 仅击败率”；选择“精确 · 击败率与平均墩数”才计算平均墩数。根据设备核心数和内存使用 1–8 个 Worker 分批求解，结果显示采样/求解耗时。叫牌可点选、撤销或粘贴；按庄家、明手、同伴切换条件，点力和长度直接填 `15-17`、`5+`，空白不限，离开输入框后应用。均型可一键切换，高级语法按需展开。

牌局标题旁提供“删除当前牌例”和“清空全部”，桌面、手机和平板均可使用。执行前会确认；删除包含对应播放分支，无法撤销，需保留时先导出。清空后只保留一副空白牌局，不恢复示例牌。

## 开发与验证

```powershell
npm ci
npm run dev
npm run build
npm test
```

Python 环境与训练命令见 [docs/python-environment.md](docs/python-environment.md)。DDS 原生对照需要先运行 `scripts/build_dds.py`；上游在 `vendor/dds` 子模块中固定提交。浏览器流程脚本为 `scripts/validate_interactions.mjs` 和 `scripts/validate_revision.mjs`，默认连接本地 5173，可通过 `TRICKTRACE_URL` 验证部署站点。OCR 验证脚本连接开发服务器读取私有验证图片。

生产部署：`npx wrangler pages deploy dist --project-name tricktrace --branch master`。模型、OCR 引擎、WASM 与字体均随站点托管；原始测试图片仅保存在私有仓库 `images/`，不打包到公开网页。字体采用 OFL 授权的 Noto Sans SC，WOFF2 按 Unicode 范围加载。

## 当前边界

这是持续开发的测试版，未完成原始计划的全部验收。当前 5 张完整手牌截图及 2 张部分手牌截图的回归通过，部分牌支持旋转明手、实际方位与当前墩识别；模糊定约显示为待核对候选。20 张新生成的保留牌谱测试为 19 张整图全对，1039/1040 张牌正确。缩小并重新压缩的截图仍有漏牌/错牌，不能保证任意截图全对。投入与简单挤牌已增加残局分支验证，双挤/连续挤牌仅标记条件结构，复杂挤牌变种尚未全部验证。详见 [docs/validation/status.md](docs/validation/status.md)。每轮实际修改记录在 [agent.md](agent.md)。
