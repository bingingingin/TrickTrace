# 功能交付检查表

这是对用户实施计划的逐项检查，不将界面入口等同于验收完成。

| 功能 | 当前实现 | 尚需完善/验证 |
| --- | --- | --- |
| 网页部署 | Cloudflare Pages 公开测试版 | 真实手机性能 |
| 手动输入 | 连续点选、四家文本同步、副号联动局况 | 更丰富的残局录入流程 |
| 图片输入 | 上传/拖放/粘贴、本地 ONNX 与 Tesseract、候选框和手工校对 | 低清、扇形、竖排明手；方位、定约和当前墩元数据自动识别 |
| PBN/DLM/LIN | 导入器和基础格式测试、多牌局切换 | 扩充真实编码/注释/变体覆盖，PBN 原始出牌记录导出 |
| 四明手表/Par | 20 格表、计分、自动后台计算并缓存 | 更广泛实际手机耗时验证 |
| 逐张求解 | 全部合法牌结果、并列最优、损失墩数、撤销回退 | 更多原记录失误定位样本 |
| 完整最优样例 | 从当前位置求解到结束、分支、修改首攻、按墩播放 | 单独展示指定首攻相对最优防守的损失 |
| 保存与恢复 | 浏览器本地会话、项目 JSON | 大型多牌局项目压力测试 |
| 基础战术 | 将吃、忍让、飞牌结构、交叉将吃 | 策略必要性与命名的更多反例 |
| 投入/简单挤牌 | 限定残局范围内结构检查与 DDS 分支验证 | 破坏进手、共同看守、强制程度的更多独立案例 |
| 复杂挤牌 | 双挤/连续挤牌条件结构提示 | 三门、连续、将吃和进手相关挤牌的完整类别验收 |
| 两家牌 | 硬约束采样、同样本候选比较、实验估计 | 真实信息集策略评估；仍存在策略融合误差 |
| 网站抓牌/插件/赛事 | 未实现 | 按计划不在本轮范围 |

验证入口及证据见 `docs/validation/status.md`。识牌/战术测试失败必须保留缺口，不允许通过补牌或改写战术说明制造通过结果。
