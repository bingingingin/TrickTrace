# J 漏识别修复与识别耗时验证

本次修改针对文字牌谱中的两种漏 J：整行 OCR 将独立的 Q、J 合并为 Q；字体间距使 QJ/KJ 在二值图像中连成一个组件。修复仍依据截图像素和现有字形模型，不根据缺牌清单补齐手牌，也没有更换模型或降低输入分辨率。

## 准确率结果（2026-09-08 本地 Chrome）

| 数据组 | 整图与已标注状态全对：修改前 → 修改后 | 漏牌：修改前 → 修改后 | 误牌：修改前 → 修改后 |
| --- | --- | --- | --- |
| 原始截图 | 7/7 → 7/7 | 0 → 0 | 0 → 0 |
| 开发字体牌谱 | 68/80 → 73/80 | 17 → 8 | 2 → 2 |
| 独立留出牌谱 | 19/20 → 19/20 | 1 → 1 | 0 → 0 |
| 缩放/JPEG 变体 | 7/14 → 7/14 | 19 → 19 | 2 → 2 |

开发集的 6 处漏 J 全部恢复，另恢复 3 张粘连的 K；正确牌张由 4143/4160 增至 4152/4160（99.81%）。121 个输入逐项比较没有新增错误。完整前后差异在 [ocr-j-quality-20260908.json](ocr-j-quality-20260908.json)。

本轮变体的“全对”还检查标签内的发牌方、局况和引牌方，比旧 `ocr-variants.json` 仅检查手牌、定约和当前墩的条件更严格，因此修改前后都是 7/14，不能与旧口径的 8/14 直接比较。低清变体中仍有 1 处漏 J，文字牌谱中仍有 Q/8 等其他失败；不代表任意截图已能无误识别。

`npm test` 的 268 项测试通过，最终识别代码的 `npm run build` 通过。本报告为本地验证，不更改线上发布状态。

## 处理规则

- 对整行 OCR 合并的 QJ，要求字形模型分别确认 Q、J，置信度均至少 0.98，并核对同一行、相邻位置及合并字框的覆盖范围。
- 对粘连组件，仅在低置信度、宽高比符合条件时尝试六个切分位置。切口必须是局部细连接，不能同时穿过字符上、下两部分；左右组件分别识别成 Q/K 和 J，且置信度均至少 0.98，才接受切分。
- 一批切分候选只做一次模型推理。保留未通过条件的原始组件。

置信度是模型分数，不是经过校准的正确概率。开发过程中出现过普通 Q 被误拆成 KJ 的反例，最终增加了连接位置和跨度限制，并将该原始样本纳入完整回归。

## 提速方式

- 形状分析复用模型输入中的归一化字形，避免再次分配 Canvas、旋转和采样。
- 删除低清平铺四手牌的重复整行 OCR。原有流程完成四次 OCR 后，在 `flatFourHands` 分支用原始牌角候选整体覆盖结果；删除该段不改变最终候选来源。
- 保留有效的整图识别、单字符复核、扇形牌处理和未知牌提示。

## 单独测速结果

同一台电脑、Chrome、相同 7 张原始截图及顺序，先旧版后新版，各串行跑一轮；本任务的其他验证已经结束。前后均为 7/7 全对。

| 指标 | 修改前 | 修改后 | 耗时减少 |
| --- | --- | --- | --- |
| 7 图总识别耗时 | 134.086 秒 | 83.291 秒 | 37.88% |
| 单图耗时中位数 | 20.740 秒 | 13.651 秒 | 34.18% |

逐图数据、源码 blob 标识见 [ocr-j-timing-20260908.json](ocr-j-timing-20260908.json)。例如“防守分析1.jpg”仅从 17.502 秒降至 17.265 秒，说明并非每种布局都有相同收益。这是桌面单轮观测，系统负载可能变化，未作为手机或所有图片的固定提速比例。

## 验证方式

`scripts/benchmark_ocr.mjs` 在 Chrome 中调用实际识别 Worker。每张图片重新创建 Worker，与应用上传行为一致；记录从调用 `recognize` 到返回的时间，包含图片解码、Worker 和模型初始化、识别及资源释放，不包含测试输入的下载与变体生成。

四组数据分别统计：7 张有标签原始截图、80 张开发字体牌谱、20 张独立留出牌谱、14 张原图缩放/JPEG 变体。原图与变体还检查已有标签中的定约、发牌方、局况、引牌方和当前墩。留出集不参与本次修复调试。

分别在修改前后运行：

```powershell
node scripts/benchmark_ocr.mjs artifacts/ocr-before.json
node scripts/benchmark_ocr.mjs artifacts/ocr-after.json
node scripts/compare_ocr_benchmarks.mjs artifacts/ocr-before.json artifacts/ocr-after.json docs/validation/ocr-comparison.json
```

比较脚本要求两次图片集合完全一致，并逐张检查是否新增漏牌、误牌、未知手牌覆盖或状态错误；发现退步以非零状态退出。`OCR_FILTER` 可以选取数据组或文件名，`OCR_RESUME=1` 可续跑同一版本的中断记录。不同代码版本不可混用续跑结果。

`OCR_CONCURRENCY=3` 可并行跑准确率样本；测速须使用默认的单页串行模式。

批量准确率回归可能与其他检查并行，不能直接据此声称提速。性能结果另用没有其他本任务检查并行运行的前后测量报告；桌面测量不代表手机耗时。
